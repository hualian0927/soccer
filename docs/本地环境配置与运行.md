# SoccerNetGSR 足球技战术分析项目：本地环境配置与运行

> 历史说明：当前 `code` 分支请以 [ENVIRONMENT.md](ENVIRONMENT.md)、[RUNNING.md](RUNNING.md) 和 [API_INTEGRATION.md](API_INTEGRATION.md) 为准。下文保留旧版路径与依赖快照，不应当作当前完整流程。

本文说明如何在一台新的 Linux 或 Windows WSL2 机器上配置本项目，运行 SoccerNetGSR 视觉底座、L1 事件分析和本地网页 Demo。

仓库只保存代码和配置，不包含模型权重、比赛视频、视频抽帧、数据集和生成结果。网页 Demo 在没有本地素材时使用内置占位界面，上传视频后会自动生成当前素材的预览图。

## 1. 已验证环境

当前开发环境如下，其他相近版本通常也可运行：

| 项目 | 已验证版本 |
| --- | --- |
| 系统 | Ubuntu on WSL2 |
| GPU | NVIDIA GeForce RTX 4070 Laptop GPU，8 GB |
| NVIDIA 驱动 | 561.00 |
| Conda | 25.5.1 |
| Python | 3.10.20 |
| PyTorch | 2.5.1 + CUDA 12.1 |
| torchvision / torchaudio | 0.20.1 / 2.5.1 |
| FFmpeg | 4.4 |
| Node.js / npm | 22.22.1 / 10.9.4 |

建议使用 NVIDIA GPU。仅运行已有 GSR JSON 的 L1 分析可以使用 CPU，但完整视频检测、跟踪和球场映射会明显变慢。

## 2. 克隆仓库

```bash
git clone git@github.com:hualian0927/soccer.git
cd soccer
```

没有配置 SSH 时也可以使用：

```bash
git clone https://github.com/hualian0927/soccer.git
cd soccer
```

## 3. 系统依赖

Ubuntu/WSL2 推荐安装：

```bash
sudo apt update
sudo apt install -y build-essential git libglib2.0-0 libgl1
```

如果 WSL 中无法识别 GPU，先在 Windows 安装支持 WSL2 的 NVIDIA 驱动，并确认以下命令有输出：

```bash
nvidia-smi
```

## 4. 创建 `sports` Conda 环境

网页后端默认调用名为 `sports` 的 Conda 环境，因此建议保持该名称：

```bash
conda create -n sports python=3.10 ffmpeg=4.4 -c conda-forge -y
conda activate sports
python -m pip install --upgrade pip setuptools wheel
```

安装与本机 CUDA 匹配的 PyTorch。当前验证组合为 CUDA 12.1：

```bash
pip install torch==2.5.1 torchvision==0.20.1 torchaudio==2.5.1 \
  --index-url https://download.pytorch.org/whl/cu121
```

然后安装项目依赖：

```bash
pip install numpy cython
pip install -r requirements.txt
pip install SoccerNet==0.1.62 ultralytics==8.4.37
pip install git+https://github.com/KaiyangZhou/deep-person-reid.git --no-build-isolation
pip install -e . --no-build-isolation
```

`JERSEY_MODE=llama` 才需要 `unsloth` 和对应 LLaMA 权重；默认 CLIP/颜色分类路径不需要配置该可选模块。

安装完成后检查：

```bash
python -c "import torch, cv2; print(torch.__version__, torch.cuda.is_available(), cv2.__version__)"
ffmpeg -version
```

## 5. 模型权重

模型不会提交到 Git。可尝试运行仓库提供的下载脚本：

```bash
python download_properties.py
```

完整 GSR 流程至少需要下列文件：

```text
checkpoints/
├── yolox_soccernet.pth.tar
├── sports_model.pth.tar-60
├── SoccernetGSR_EfficientNet_Best.pth
├── CLIP_Jersey.pth
└── osnet_x1_0_market_256x128_amsgrad_ep150_stp60_lr0.0015_b64_fb10_softmax_labelsmooth_flip.pth
```

近景个人动作功能还会使用 YOLO Pose 权重，例如根目录下的 `yolov8n-pose.pt`。权重路径可在 `configs/config.yaml` 和对应命令行参数中调整。

## 6. 准备本地视频

任意 MP4 可以放在不提交的目录，例如：

```text
soccer_input_dataset/
└── input_match.mp4
```

视频和输出目录已被 `.gitignore` 排除。SoccerNet 视频受 NDA 和非商业条款约束，不应加入仓库或转发给未授权人员。

## 7. 运行完整 GSR 视觉处理

以下示例使用蓝衣队、白衣队、红衣裁判，以及归入蓝队的黄绿色门将：

```bash
conda activate sports

python run_local_video_gsr_visualization.py \
  --input-video soccer_input_dataset/input_match.mp4 \
  --video-name local-match \
  --work-root soccer_input_dataset/outputs/local-match/gsr_work \
  --output-video soccer_input_dataset/outputs/local-match/gsr_visualized.mp4 \
  --team0-colors blue \
  --team1-colors white \
  --referee-colors red \
  --goalkeeper-team0-colors yellowgreen \
  --recall-optimized \
  --overwrite
```

长视频初次处理耗时取决于 GPU、分辨率和帧数。调试时可以加 `--max-frames 900` 先处理约 30 秒。

## 8. 运行 L1 事件分析

完整 GSR 流程会生成 SoccerNetGS 格式 JSON。以该 JSON 为输入运行模块化分析：

```bash
python run_tactical_analysis.py \
  --json-path soccer_input_dataset/outputs/local-match/gsr_work/SoccerNetGS/test/local-match/local-match.json \
  --input-video soccer_input_dataset/input_match.mp4 \
  --output-dir soccer_input_dataset/outputs/local-match/l1_report \
  --config configs/tactical_analysis.yaml
```

主要输出包括：

```text
tactical_analysis_report.json
tactical_analysis_report.md
l1_event_timeline.json
l1_event_timeline.csv
l1_summary.json
set_piece_manifest.csv
```

定位球证据片段可单独导出：

```bash
python export_set_piece_clips.py \
  --input-video soccer_input_dataset/input_match.mp4 \
  --manifest soccer_input_dataset/outputs/local-match/l1_report/set_piece_manifest.csv \
  --output-dir soccer_input_dataset/outputs/local-match/set_piece_clips
```

## 9. 启动本地网页 Demo

安装前端依赖：

```bash
cd web_preview
npm ci
```

启动开发服务器：

```bash
npm run dev
```

浏览器访问：

```text
http://localhost:4173/
```

网页上传新视频后，同一端口下的本地服务会依次调用：

```text
run_local_video_gsr_visualization.py
  -> make_tactical_visualization_video.py
  -> run_tactical_analysis.py
  -> export_set_piece_clips.py
  -> FFmpeg H.264 网页兼容转码
```

处理文件、任务状态和人工复核记录保存在 `web_preview/runtime/`，不会提交到 Git。

## 11. 常见问题

### 网页上传后一直显示处理中

确认启动网页的终端能够执行 `conda run -n sports python ...`，且模型权重路径完整。终端会显示具体失败阶段。

### 视频可以生成但浏览器无法播放

浏览器播放器推荐 H.264 + `yuv420p`。网页处理链会自动转码；手工生成的视频可使用 FFmpeg 转换。

### CUDA 不可用

检查 Windows NVIDIA 驱动、WSL2 GPU 支持，以及 PyTorch 安装的 CUDA 版本。不要在 WSL 内额外安装完整 Linux NVIDIA 驱动。

### 只想开发事件分析，不运行深度模型

准备一个已有的 SoccerNetGSR JSON，直接执行第 8 节。`tactical_analysis/` 本身只依赖结构化轨迹、NumPy/Pandas 等轻量组件。
