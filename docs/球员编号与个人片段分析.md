# 球员编号与个人片段分析

更新日期：2026-10-06。

## 功能与入口

本地前端：`http://localhost:4173`。进入“项目”中的“五分钟球员编号与个人复盘”，打开视频；视频下方启用“球员编号”，点选画面中的编号或下拉选择，设置开始/结束秒数，再生成片段分析。

默认不显示编号、选人框和个人报告；关闭开关即隐藏这些内容。原有整体事件、组织和空间分析不被替换。

选段限定同一镜头、最多 30 秒。跨切镜选段会被拒绝，避免拿同一编号分析不同人。编号不是球衣号码，也不承担离开画面后的长期身份识别。

## 技术路线

```text
原视频 + 既有 GSR 人员检测框
  -> BoT-SORT（运动预测、外观特征、稀疏光流相机运动补偿）
  -> 上衣区域颜色冲突约束 + 短时原轨迹续接
  -> 切镜隔离 + 临时编号逐帧数据
  -> 网页按原视频时间绘制可选编号
  -> 用户指定编号与时间段
  -> 原片截取、选人框、12 张时序证据、统计报告
  -> 对已核看的示例附观察、技战术解释和训练建议
```

跟踪核心使用 Ultralytics 的 BoT-SORT，而非从零实现。YOLOv8n 用于少框场景补检与通用外观特征；颜色约束用于抑制明显不同球衣间的身份跳转，不是新训练的球队分类网络。

实际限制：同色球员完全遮挡、低分辨率、漏检、急剧变焦仍可能换号或跟错。本轮功能是可检查的初版，不承诺“只要人在画面内就百分之百不换号”。需要通过跨场景 ID Switch/IDF1 评测继续验收。

## 哪些分析是自动的

| 输出 | 来源 | 边界 |
| --- | --- | --- |
| 可见/已检测时长、跟踪覆盖率 | 选定编号的逐帧记录 | 不是动作识别准确率；出画、遮挡、漏检都降低数值 |
| 图像位置变化 | 图像归一化框位置 | 含镜头移动，不是米制速度或跑动距离 |
| 球框邻近帧数 | 人脚附近和球框中心的像素距离 | 不是触球次数，也不是控球时长或传球成功数 |
| 选人片段与证据图 | 原视频、编号记录 | 检测缺失处不伪造真实观测 |
| 技战术评语 | 本轮助手直接核看的固定示例 | 不调用外部 API；不是教练真值 |

其他任意选段仍可导出，但语义结论标记为“待画面复核”，不会自动拿已审核示例的文字套用。已审核意见只绑定相同编号、相同时间区间；更改选人或时间会清除旧结果。

示例还绑定 `player_tracks.json` 的 SHA-256。重新生成轨迹后，如数据发生变化，旧评语不会自动沿用；需要重新核对编号与画面。

## 文件

| 文件 | 作用 |
| --- | --- |
| `workflows/players/build_player_focus_video.py` | 从原视频和 GSR JSON 生成编号数据，可选生成完整编号视频 |
| `tactical_analysis/player_tracker.py` | 基于 BoT-SORT 的上衣颜色冲突约束 |
| `tactical_analysis/player_focus.py` | 临时 ID、受约束续接、选段校验与保守统计 |
| `workflows/players/export_player_focus.py` | 选人截片、时序取证、中文报告，无外部 API |
| `web_preview/server/player-focus.js` | 本地选段导出接口、路径限制、串行执行与超时 |
| `web_preview/src/PlayerFocus.jsx` | 隐藏开关、逐帧选人、选段、结果展示 |
| `web_preview/scripts/verify-player-focus.mjs` | 桌面/手机交互及导出回归测试 |
| `tests/test_player_focus.py` | 编号续接、切镜隔离、球邻近与色彩约束测试 |

已有五分钟输出目录：`soccer_input_dataset/outputs/test_5min_player_focus/`。

- `player_numbered.mp4`：完整编号视频，下载播放时编号固定显示。
- `player_tracks.json`：网页动态绘制编号所需的逐帧数据。
- `player_reviews.json`：本轮实际检查过的示例意见。
- 网页主视频仍为原有框选版；编号为可关闭的网页图层，没有另行在整片烧录个人评语。

## 运行

```bash
conda activate sports
python -m workflows.players.build_player_focus_video \
  --video soccer_input_dataset/test_5min.mp4 \
  --gsr-json soccer_input_dataset/outputs/test_5min_layered_v2/identities.json \
  --output-dir soccer_input_dataset/outputs/test_5min_player_focus --render

cd web_preview
npm run dev -- --host 127.0.0.1 --port 4173
```

新上传视频：现有本地分析流程完成后会生成 `player_focus/player_tracks.json` 并返回前端入口，不会因为启用编号而额外调用外部模型。整条旧分析链是否调用 API 仍取决于原有环境配置；本轮测试服务未启用 API 密钥。

导出接口：`POST /api/player-review`，参数为 `trackingPath`、`playerId`、`start`、`end`。Python 可通过 `SPORTS_PYTHON` 指定；默认使用本机 sports 环境。FFmpeg 优先取 PATH，缺少时取当前 Python 同目录的 FFmpeg。

## 后续优先项

### 本轮验证记录

- 完整 `test_5min.mp4`：8,997 帧，299.90 秒，1280×720；编号视频为 H.264 + AAC。
- 帧内重复编号检查：0 帧重复。切镜检测分出 25 个镜头区间，其中快速切换可能过分段，尚未经完整真值核验。
- 本轮共出现 724 个临时编号，包含切镜、出入画、漏检断轨和可能的错误断轨，**不是 724 名真实球员**，也说明全片身份连续性还需要专项优化。
- 直接核看两个示例各 12 张证据图：`#335` 的 143.5–147.5 秒中路前插/推进，`#489` 的 206.7–208.9 秒门将迎回传/出球。
- 编号观测覆盖率分别为 98.3%、83.3%；门将摆腿阶段仍有漏框。该指标只用于描述观测完整性，不能报告为跟踪正确率。
- 单元测试 7 项、既有 review 相关测试 54 项、框架测试 1 项通过；前端生产构建通过。桌面/手机验证编号默认隐藏、点选、导出、审核评语、关闭隐藏和路径拒绝。
- 新视频上传后的编号阶段已接入，但本轮未另跑一整条新素材检测链；本轮完整处理和验收素材为已有五分钟视频。

### 下一步

1. 人工标注同队交叉、短遮挡、近远景切换的 ID 连续性，评估而不是只看框数量。
2. 加入用户纠正身份、分裂错误轨迹和合并正确片段的能力。
3. 为个人分析补上高质量球场坐标和动作模型，避免把屏幕位移当跑动量。
4. 引入模型时以本轮“观察/解释/建议/证据边界”结构为契约，保留拒答、补帧和人工确认。
5. 原视频、多机位及摄像头建议见 [融合调研](全景与对侧视频融合技战术分析调研.md)。
