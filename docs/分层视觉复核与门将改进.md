# 分层视觉复核与门将改进

更新日期：2026-09-20

## 1. 本次交付

- 输入：`soccer_input_dataset/test_5min.mp4`。
- 输出：`soccer_input_dataset/outputs/test_5min_layered_v2/test_5min_boxes.mp4`。
- 时长 299.904 秒，1280×720、30 FPS，H.264 视频、AAC 原声。
- 网页：`http://localhost:4173/` → 项目 → 五分钟分层技战术复盘 → 五分钟分层技战术分析。
- 主画面只有原始视频和人物、足球检测框；不叠加战术板、轨迹、字幕面板或暂停解说。原片自带的转播文字保留。
- 旧版成片与历史项目保留，新上传同源五分钟视频命中新版 SHA-256 缓存。

## 2. 分层输出

| 层级 | 本版内容 | 证据与限制 |
| --- | --- | --- |
| L1 事件 | 射门、定位球、出界、传球、防守干预、门将候选的抽样复核 | 节点跳转原片，另有审核片段、逐帧图片和模型反馈；不是全量事件真值 |
| L2 统计 | 按事件类分别列出全片候选、送审、视觉支持、视觉否定数量 | 不能把送审样本的支持比例当作全场准确率；暂不计算真实扑救成功率、传球成功率和正式 xG |
| L3 组织 | 复用已有进攻链中的可见传球、推进序列 | 已审且被否定或有冲突的终点射门不进入该射门链；其余动作仍是候选，切镜可能截断链路 |
| L4 空间 | 复用已有阵型、宽度纵深、局部人数优势和防守空档 | 只表示可见区域及现有标定下的几何候选，不代表完整 22 人阵型或教练确认结论 |

L1-L4 是分析深度，不等同于开发优先级 P0-P4。本次没有重新训练战术识别模型，也没有把几何规则称作论文完整复现。

## 3. 处理链

```text
视频 → 检测跟踪及场地映射 → 球衣/轨迹身份复核
  ├─ 原片 + 检测框 → H.264/AAC 网页播放
  └─ 19 个分析器 → 算法候选及空间指标
       → 抽样选节点 → 前后各 5 秒原片 + 41 张图片
       → DeepSeek 图像审核 → 门将独立复审
       → 支持 / 否定 / 不确定 / 分歧
       → L1-L4 JSON → 网页节点、统计与分析文字
```

新视频通过本机 Vite 后端在 `sports` Conda 环境调用上述 Python 代码。未设置 `DEEPSEEK_API_KEY` 时只准备证据，不伪造模型结论；密钥仅从后端环境变量读取。

## 4. 门将识别改动

旧五分钟 GSR 缓存没有 goalkeeper 角色，必须先修复角色输入，不能仅扩大二维距离阈值。

1. 复用上半身球衣颜色、多帧轨迹投票、身份不一致轨迹拆分；门将/裁判需要至少 3 次颜色证据。独立生成 `identities.json`，不覆盖原始缓存。
2. 门将候选同时检查门区位置、二维球门将距离、持续时间和原画面中球与人物框的接近程度。二维接近但图像明显相距较远时拒绝。
3. 对轨迹时间断裂、异常坐标跳变和过长片段分段；时间定位到球门将最近接近的实际帧，而非很早的接近起点。
4. 标定不可用时，仅允许连续图像接近生成低置信的触球待复核候选。
5. 不再把横向移动直接判成侧扑。扑救需要视觉身份、触球与来球证据；规范性和成功率保持未确认。
6. 送审时附同帧同轨迹的门将局部图，并针对中心动作窗口独立复审。两次结果不一致时，网页不采纳具体动作结论；原始模型意见可展开审阅。

**真实限制**：本次 3:28 左右画面仍出现模型把站立脚下处理描述成倒地扑救的错误。当前已将这类意见隔离为“动作类型存在分歧”，没有把它当作扑救统计。独立复审不是准确性保证，后续仍需要姿态/动作模型与门将人工真值集。

门将球衣默认先验是黄/绿色归蓝队，仅服务当前样例，不能保证门将归队正确。其他比赛需要显式配置颜色；裁判、门将身份仍属于候选。

## 5. 审核片段和模型文字

- 每个节点以候选时间为中心，前 5 秒、后 5 秒；视频起止处截断到真实时长。
- 默认在窗口内均匀采样 41 张全景图，约 4 FPS，保存实际帧时间。门将存在同帧轨迹框时增加局部图。
- 保存原片的 10 秒 MP4，而不是把带结论文字的成片再次喂给模型。
- 网页展示候选观察、分析参考、待确认部分。分歧结论不作为事实展示；原始意见保留方便核查。
- 当前配置使用 `deepseek-flash` 图像接口，参见 [DeepSeek 官方视觉说明](https://api-docs.deepseek.com/guides/vision/)。本地审核 JSON 中保留模型名、usage、证据索引、请求版本和独立复审信息，不保存密钥。
- 默认每视频最多抽样 20 个候选；不是把全部检测帧送审。短窗口可能看不到迟到的重启动作，此时应保持未知，后续可另加扩展上下文，不强猜类型。

## 6. 出界不等于定位球类型确认

球场外检测点可能来自漏检误配、标定误差或高空球落地投影偏差。本版要求连续轨迹从场内越过边界、连续场外观测及合理运动速度，才生成“出界候选”。

即使原画面确认球整体出界，也不能仅凭这一点区分角球、球门球和界外球，还要知道越过哪条线、最后触球方及后续重启；任意球、点球还涉及裁判判罚。出界候选不会自动计入角球或任意球次数。

| 文件 | 作用 |

| `web_preview/server/local-analysis.js` | 网页上传调用本地流水线、载入分层结果 |

在仓库根目录执行：

```bash
conda activate sports
python -m workflows.review.build_layered_tactical_review \
  --report-json soccer_input_dataset/outputs/test_5min_layered_v2/report/tactical_analysis_report.json \
  --video soccer_input_dataset/test_5min.mp4 \
  --output-dir soccer_input_dataset/outputs/test_5min_layered_v2
```

上述命令复用已保存审核，不产生 API 请求；首次调用模型需通过安全的环境配置设置 `DEEPSEEK_API_KEY` 并加 `--review-api`。缓存签名包含事件、视频大小/修改时间、采样数量和提示词版本，避免直接套用旧审核。

下一步应优先给这 17 个节点补人工真值，尤其门将脚下处理、接回传、接球与扑救的区分，再考虑扩大调用数量。
